# agent-template

> Your personal agent workspace template. Clone this for every new project.
> Pre-configured for Claude Code, Codex CLI, Cursor, and Aider.

---

## What is this?

A GitHub Template Repository that gives you a fully configured agent workspace in 2 minutes:

- `CLAUDE.md` — Claude Code reads this automatically on every session
- `AGENTS.md` — Codex CLI / Cursor / Aider compatible version
- `SECURITY.md` — security rules the agent enforces on every route
- `docs/testing/` — testing strategy: unit, integration, security, adversarial, performance
- `scripts/init-project.sh` — fills in all the blanks for your specific project
- `scripts/new-module.sh` — scaffolds a new module spec + updates CLAUDE.md

---

## How to use

### For a new project

```bash
# 1. Click "Use this template" on GitHub → create your new repo
# 2. Clone your new repo
git clone https://github.com/you/your-new-project
cd your-new-project

# 3. Run the init script — answers 6 questions, generates everything
chmod +x scripts/init-project.sh
./scripts/init-project.sh

# 4. Fill in the TODOs in the generated files (15 min)
# 5. Start Claude Code
claude
```

### Adding a new module to an existing project

```bash
./scripts/new-module.sh "Notes"
# → generates docs/specs/notes.spec.md
# → adds Notes to CLAUDE.md module table
# Fill in the spec, then tell the agent to implement it
```

### Updating module status

```bash
./scripts/update-module-status.sh "Notes" done
./scripts/update-module-status.sh "Tasks" in-progress
```

| File | Purpose |
|---|---|
| `CLAUDE.md` | Claude Code instructions — project-specific |
| `AGENTS.md` | Codex/Cursor/Aider instructions — project-specific |

The following files are **not** modified — they are universal and work for every project:

| File | Purpose |
|---|---|
| `SECURITY.md` | Security rules (attack vectors + defenses) |
| `docs/testing/TESTING.md` | 5-layer testing strategy |
| `docs/testing/VALIDATION.md` | Validation loop patterns |
| `docs/testing/ADVERSARIAL.md` | Adversarial + security test patterns |
| `docs/testing/PERFORMANCE.md` | k6 performance test guide |

## How agents use these files

### Claude Code
Reads `CLAUDE.md` automatically when you run `claude` in the project directory.
No config needed. The file is loaded at the start of every session.

### Codex CLI
Reads `AGENTS.md` automatically. Run `codex` in the project directory.

### Cursor
Reads `AGENTS.md` via its agent rules system. Also reads `.cursorrules` if you prefer
to keep a Cursor-specific file — copy AGENTS.md content there.

### Aider
Reads `AGENTS.md` automatically. Run `aider` in the project directory.

## Customizing this template for your style

Clone this repo itself and modify:

1. `CLAUDE.md` — change the universal rules to match your preferences
2. `SECURITY.md` — adjust security level (full app vs static site)
3. `docs/testing/` — adjust thresholds and required test types
4. `scripts/init-project.sh` — add more questions or stacks you use often

Then mark your fork as a GitHub Template Repository:
Settings → check "Template repository"

## Recommended workflow per project

```
Day 1: Init
  clone template → run init-project.sh → fill TODOs → commit

Week 1: Foundation
  Tell Claude Code: "Implement the auth module — read docs/specs/auth.spec.md"
  Review → commit → update module status

Per module:
  1. ./scripts/new-module.sh "ModuleName"
  2. Fill in docs/specs/modulename.spec.md  (15 min)
  3. claude "Read docs/specs/modulename.spec.md and implement end-to-end"
  4. Review diffs → merge
  5. ./scripts/update-module-status.sh "ModuleName" done

Before release:
  pnpm test:security
  pnpm test:adversarial
  pnpm test:perf
```
